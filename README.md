# 寄出之前｜中研院RCCI實驗室營業秘密情境小遊戲（v3.3）

一款以 GBA 時代俯視角像素 RPG 為靈感的純靜態網頁小遊戲。玩家扮演「中研院RCCI實驗室」的值班研究助理**小安**，與同事**阿文**、**小晴**及負責人**阿明組長**互動，透過五個獨立章節練習實驗室營業秘密保護的日常決策、紀錄留痕、文件標示、盤點歸檔、離職交接與補救應變。

- **純靜態網頁（HTML / CSS / JavaScript）**：零外部相依、無後端、無須建置流程，所有資源皆採相對路徑。
- **本機試玩方式**：在 Windows 直接雙擊開啟 `index.html` 即可於瀏覽器遊玩，不須架設伺服器；亦支援直接部署至 GitHub Pages（含專案子路徑）。
- **操作方式（GBA 掌機介面）**：
  - **移動與游標**：鍵盤方向鍵 / `WASD` 或畫面左側十字鍵（首頁與暫停選單支援經典 `▶` 游標上下選擇，亦可滑鼠點選／觸控點擊）。
  - **互動／取消**：`Space` / `Enter` 對應 `A` 鍵（互動確認）；`B` 鍵返回或關閉彈窗。
  - **START（`Esc` / `P`）**：暫停遊戲並開啟懸浮系統選單（繼續、筆記、結局圖鑑、重來本章、開關音效、返回首頁選單；重來僅重置當前章節，保留已解鎖結局）。
  - **SELECT（`Tab`）**：暫停遊戲並直接開啟「📋 值班筆記與任務進度」懸浮視窗。
  - **通關慶祝畫面**：完成章節任務時會提示回 2F 值班桌交班，交班後顯示專屬通關慶祝與評等畫面，可接著檢視完整交班紀錄或直接挑戰下一章。
- **雙樓層空間探索（1F ↔ 2F）**：
  - **1F（一樓大門大廳與觀測廊）**：大門入口、接待櫃台（訪客先於一樓報到）、大廳形象牆（核准拍照區）、休息沙發、中庭景觀窗、一樓管制實驗區觀測窗與會議廳門面；可透過左側樓梯或電梯往返二樓。進入樓層時可一次看見完整地圖。
  - **2F（二樓辦公區與量測實驗區）**：研究助理辦公區（值班電腦、值班桌）、獨立玻璃隔間的阿明組長辦公室、走廊宣導布告欄，以及門禁管制的二樓量測實驗區（阿文、白板、量測螢幕、樣品架與機台）。進入樓層時可一次看見完整地圖。
- **虛構演練情境**：角色、合作方、海報與研究資料皆為虛構演練素材（樓層空間亦經簡化與去識別化設計）。

## 章節與玩法說明

首頁提供五個章節入口，**五章皆可直接進入，無須先破完前章**（各章標有預計遊戲時間，第一章結局圖鑑可由遊戲中按 `START` 暫停選單開啟）：

1. 第一章「寄出之前」（內部識別值：`1`，預計遊戲時間：約 4 分鐘）
2. 第二章「投稿前一晚」（內部識別值：`2`，預計遊戲時間：約 5 分鐘）
3. 第三章「這份文件要怎麼標？」（內部識別值：`5`，全新章節，預計遊戲時間：約 3 分鐘）
4. 第四章「這批資料要列入清單嗎？」（內部識別值：`4`，原第三章後移，預計遊戲時間：約 5 分鐘）
5. 第五章「阿文的最後一天」（內部識別值：`3`，原第四章後移，預計遊戲時間：約 6 分鐘）

> [!NOTE]
> **舊存檔與識別值相容保證**：
> 既有章節沿用原識別值（1, 2, 4, 3）、存檔鍵（`before_sending_endings_v1`, `before_sending_ch2_endings_v1`, `before_sending_ch4_endings_v1`, `before_sending_ch3_endings_v1`）及結局紀錄；新第三章採用獨立識別值 `5` 與存檔鍵 `before_sending_ch5_endings_v1`。章節切換透過按鈕 `data-chapter` 屬性直接綁定內部識別值，舊存檔與外部連結皆能精準載入正確章節。

### 第一章「寄出之前」（下午 15:40）

下班前處理兩項可任意排序的突發任務，並保有 5 種交班結局圖鑑：

1. **先查證（確認 NDA 簽署＋版本）再提供路線**：
   到辦公區電腦讀信 → 先透過電腦「📑 查詢實驗室 NDA 合約清單」或找辦公區**阿明組長**完成 **NDA 簽署查核關卡**（確認星海科技已簽署有效 `NDA-CS-2026`、在效期內且涵蓋範圍不含原始數據與協力廠商；必要時可先回覆「正在確認中」）→ 找實驗區同事**阿文**解鎖會議用兩張圖 → 回電腦僅分享核准兩張圖，設定指定收件人唯讀與 7 天效期。
2. **誤寄後補救路線**：
   在電腦將整個 `StarSky_TestData` 資料夾設成「持連結者皆可存取」寄出 → 收到合作方詢問能否轉傳協力廠商的急信 → 立刻回電腦**停用公開連結** → 找負責人**阿明組長**完成四要素通報（發現時間、涉及資料、使用系統、目前情況）。
3. **訪客拍照雙路線**：
   - 在**訪客入口指定角度**拍形象牆（核准範圍）。
   - 或**陪同進入實驗區**看相機預覽 → 發現白板／螢幕／樣品標籤入鏡時按「暫停拍攝」→ 整理現場後重拍。

### 第二章「投稿前一晚」（晚上 18:00）

阿文在辦公區門口請玩家協助確認今晚要交的研討會海報草稿（內含三張示意圖：圖一「設備配置示意」可公開、圖二「合作方量測圖」曾用於合作會議、圖三「測試條件與結果摘要」涉及尚待確認的專利申請安排）。

可自由走動調查**辦公區電腦**、**實驗區的阿文**（說明圖二來源並解鎖替代圖）與**辦公區的阿明組長**（詢問「現在哪張圖能用？」與「整理好之後怎麼確認版本？」），並在電腦比較「原始草稿」與「目前編輯版本」、送審核准與自選檔案提交。

#### 第二章三條測試路線
1. **核准後提交**：
   - 先到辦公區電腦看草稿（此時圖二顯示「來源待確認」且替代圖鎖定）→ 到實驗區找**阿文**確認圖二原用於合作會議並取得替代圖 → 找辦公區**阿明組長**確認公開規則與專利安排 → 回電腦替換圖二、移除圖三、送交阿明組長確認 → 找**阿明組長**核准該版本 → 回電腦核對檔名後提交核准版 → 回值班桌交班。
2. **暫緩提交**：
   - 在未取得完整確認或發現合作資料公開用途／專利申請安排尚待確認時，於電腦「版本紀錄與提交投稿」分頁選擇**「暫緩上傳」** → 回值班桌交班，確認列出待確認的圖片、原因與下一步。
3. **誤傳舊版後補救（含未完成補救即交班）**：
   - 取得核准版後（或未核准前），在提交畫面故意選取未確認的舊版（如 `Poster_v1_原始草稿.pdf`）上傳 → 觸發誤傳警報。
   - **補救完成**：回電腦點「聯絡主辦方提出撤換請求」→ 找辦公區**阿明組長**回報 → 回值班桌交班確認撤換與公開狀態。

### 第三章「這份文件要怎麼標？」（下午 16:00 · 全新章節）

阿文拿著三份剛整理好的虛構文件來到 2F 辦公區，請小安（玩家）逐份檢視內容與預計用途，決定是否加上機密標示，並在顯著位置落實標記。本章為約三分鐘的引導關，重點在於區分公開宣傳品與含有未公開自研 know-how 的技術資料，落實顯著標記並由接手人建立正確保管與分享認知。

#### 三份虛構文件判定與預覽
1. **文件一：可公開的活動海報**（星空計畫研發成果發表交流會活動海報）
   - **內容與用途**：活動時間、地點、議程大綱與公開報名連結，無任何未公開自研技術細節。預計張貼於 1F 大廳形象區並公開廣發。
   - **正確標示**：【一般 / 公開 (Public)】（無須標註機密）。
   - **選錯回饋**：若選標註機密，提示：「⚠️ 這是要對外張貼宣傳的公開活動海報，若誤標機密會導致無法公開宣傳張貼；內容無未公開技術，確認為公開資訊即可不標機密。」允許當場重選！
   - **版面預覽**：維持乾淨清爽的公開宣傳版面，右下角標記「公開宣傳版」。
2. **文件二：含未公開調校方法的電子簡報**（StarSky_儀器調校與最佳化參數流程.pptx）
   - **內容與用途**：24 頁內部報告，記載團隊自行摸索數月的調校參數、避坑經驗與最佳量測條件（屬未公開自研 know-how）。供本週專案內部技術檢討會使用。
   - **正確標示**：【機密 (Confidential)】。
   - **選錯回饋**：若選公開，提示：「⚠️ 這份簡報包含團隊未公開的調校方法 know-how，若未標示機密，接手人或他人很容易誤以為是一般技術分享而轉發外流！」允許當場重選！
   - **版面預覽**：簡報首頁封面右上角顯著標註紅色「機密 CONFIDENTIAL」徽章；每頁投影片頁腳（Footer）標註「機密文件 · 限專案內部使用 · 未經授權禁止翻拍轉傳」。
3. **文件三：含未公開量測結果的紙本研究紀錄**（關鍵樣品量測原始手稿）
   - **內容與用途**：裝訂紙本實驗紀錄簿，記載樣品關鍵低溫量測原始曲線與數據聯，屬未公開第一手紀錄。供接手人小晴驗收數據並鎖入 2F 公文櫃。
   - **正確標示**：【機密 (Confidential)】。
   - **選錯回饋**：若選公開，提示：「⚠️ 紙本紀錄一旦放在桌面或被他人翻閱，若無首頁顯著機密標示，他人無法第一時間辨識並依機密規範鎖入公文櫃！」允許當場重選！
   - **版面預覽**：封面與首頁顯著加蓋紅色「【 機 密 】CONFIDENTIAL · 管制編號：CS-DOC-2026-03」印章與保管人註記。

#### 小晴接手交接與核心金句
- 完成三份文件標示後，玩家前往 2F 辦公區找接手同事**小晴**交接。
- 小晴逐一檢查文件，說明後續保管作為：
  - 活動海報：直接拿去 1F 大廳形象區公布欄張貼宣傳。
  - 調校簡報：存入受控加密資料夾；廠商索取時先找阿明組長確認 NDA 與授權名單，絕不私自轉寄。
  - 紙本手稿：首頁蓋有機密紅章，核對後立刻鎖進 2F 防火公文櫃，離開座位落實桌面淨空；日後借閱需在清冊登記。
- **核心金句**：小晴鄭重提醒玩家：
  > **「標示讓接手人知道怎麼處理，分享前仍要確認對象及權限。」**
- 完成交接後，可直接向小晴或回 2F 值班桌交班，解鎖 S 級通關慶祝與交班紀錄。

### 第四章「這批資料要列入清單嗎？」（下午 16:30 · 原第三章後移）

阿文在 1F 實驗區拿出同一個虛構量測計畫（星空計畫）的三組資料，請主角小安協助確認哪些需要列入研發成果清單。重點在於辨識資料類型（公開教學重現、未公開自研 know-how、已送件專利）、落實清單五欄位（資料名稱或範圍、資料類型、保護原因、存放位置、負責人），並在專利申請案公開時，及時且精確地動態更新原有項目。

#### 第四章測試路線
1. **完整標準通關（S 級評價）**：
   在 1F 實驗區找阿文辨識三組資料卡 → 上 2F 電腦確認清單草稿五欄位並儲存 → 收到專利公開通知後選擇「只更新已公開的項目」→ 找 2F 小晴核對清單三重點（盤點批次、位置負責人、公開保護界線）→ 完成第四章交班。
2. **草稿誤勾選公開方法重現**：提示該項僅為重現公開教學且無自家改良，留作一般紀錄即可，當場取消勾選後儲存。
3. **專利公開誤標整個計畫**：提示調校紀錄未納入申請仍屬未公開 know-how，重新選擇「只更新已公開的項目」。

接續前章整理好的資料清冊，阿文即將離開實驗室，詢問能否先保留原本的專案資料夾權限以便下個月改論文。玩家需運用 1F 與 2F 樓梯／電梯完成跨樓層交接、切換「阿文／小晴」存取預覽視角、終止原權限、設定限期合作授權並收回實體門禁卡。

#### 第五章三條測試路線
1. **完成交接與限期授權**：
   請 2F 阿文移交原始紀錄 → 在 2F 值班電腦為小晴開通專案權限 → 請 2F 小晴實測開啟並確認接收 → 下樓找 1F 阿明組長核定兩張圖 30 天授權範圍並於 1F 櫃台收回門禁卡 → 回 2F 電腦終止阿文原權限並設定兩張圖 30 天限期授權 → 與 2F 阿文確認保密提醒 → 回 2F 值班桌交班。
2. **太早終止權限後補救**：
   原始紀錄移交前先終止原權限導致交接中斷 → 找 1F 阿明組長啟動管理員協助單獨移交指定紀錄（不恢復整包權限）→ 請小晴實測開啟後補齊交接。
3. **保留原權限授權過廣**：
   點選「保留原權限」，檢視權限過廣之風險並可選擇直接交班或回頭補救。

## 部署到 GitHub Pages（直接上傳）

本資料夾內的檔案可直接上傳至 GitHub Pages。

### 部署步驟
1. 在 GitHub 上建立一個新的公開倉庫（Repository，例如 `before-sending-game`）。
2. 將 `直接上傳github` 資料夾內的**所有檔案與子資料夾直接上傳到該倉庫的根目錄**：
   - `index.html`
   - `README.md`
   - `audio/`
   - `css/`
   - `js/`
3. 進入 GitHub 倉庫的 **Settings → Pages**：
   - **Source** 選擇 `Deploy from a branch`
   - **Branch** 選擇 `main`（或 `master`），資料夾選擇 `/ (root)`
   - 點擊 **Save**。
4. 等候約 1~2 分鐘，即可透過 GitHub Pages 提供之網址在任何電腦、手機或平板瀏覽器中暢玩！

# 寄出之前｜中研院RCCI實驗室營業秘密情境小遊戲（v3.0）

一款以 GBA 時代俯視角像素 RPG 為靈感的純靜態網頁小遊戲。玩家扮演「中研院RCCI實驗室」的值班研究助理**小安**，與同事**阿文**、**小晴**及負責人**阿明組長**互動，透過四個獨立章節練習實驗室營業秘密保護的日常決策、紀錄留痕、盤點歸檔、離職交接與補救應變。

- **純靜態網頁（HTML / CSS / JavaScript）**：零外部相依、無後端、無須建置流程，所有資源皆採相對路徑。
- **本機試玩方式**：在 Windows 直接雙擊開啟 `index.html` 即可於瀏覽器遊玩，不須架設伺服器；亦支援直接部署至 GitHub Pages（含專案子路徑）。
- **操作方式（GBA 掌機介面）**：
  - **移動與游標**：鍵盤方向鍵 / `WASD` 或畫面左側十字鍵（首頁與暫停選單支援經典 `▶` 游標上下選擇，亦可滑鼠點選／觸控點擊）。
  - **互動／取消**：`Space` / `Enter` 對應 `A` 鍵（互動確認）；`B` 鍵返回或關閉彈窗。
  - **START（`Esc` / `P`）**：暫停遊戲並開啟懸浮系統選單（繼續、筆記、結局圖鑑、重來本章、開關音效、返回首頁選單；重來僅重置當前章節，保留已解鎖結局）。
  - **SELECT（`Tab`）**：暫停遊戲並直接開啟「📋 值班筆記與任務進度」懸浮視窗。
  - **通關慶祝畫面**：完成章節任務時會提示回 2F 值班桌交班，交班後顯示專屬通關慶祝與評等畫面，可接著檢視完整交班紀錄或直接挑戰下一章。
- **雙樓層空間探索（1F ↔ 2F）**：
  - **1F（一樓大門大廳與觀測廊）**：大門入口、接待櫃台（訪客先於一樓報到）、大廳形象牆（核准拍照區）、休息沙發、中庭景觀窗、一樓管制實驗區觀測窗與會議廳門面；可透過左側樓梯或電梯往返二樓。
  - **2F（二樓辦公區與量測實驗區）**：研究助理辦公區（值班電腦、值班桌）、獨立玻璃隔間的阿明組長辦公室、走廊宣導布告欄，以及門禁管制的二樓量測實驗區（阿文、白板、量測螢幕、樣品架與機台）。
- **虛構演練情境**：角色、合作方、海報與研究資料皆為虛構演練素材（樓層空間亦經簡化與去識別化設計）。

## 章節與玩法說明

首頁提供四個章節入口，**四章皆可直接進入，無須先破完前章**（第一章結局圖鑑可由遊戲中按 `START` 暫停選單開啟）：

1. 第一章「寄出之前」
2. 第二章「投稿前一晚」
3. 第三章「今天的紀錄，明天找得到」
4. 第四章「阿文的最後一天」

### 第一章「寄出之前」（下午 15:40）

下班前處理兩項可任意排序的突發任務，並保有 5 種交班結局圖鑑：

1. **先查證（確認 NDA 簽署＋版本）再提供路線**：
   到辦公區電腦讀信 → 先透過電腦「📑 查詢實驗室 NDA 合約清單」或找辦公區**阿明組長**完成 **NDA 簽署查核關卡**（確認星海科技已簽署有效 `NDA-CS-2026`、在效期內且涵蓋範圍不含原始數據與協力廠商；必要時可先回覆「正在確認中」）→ 找實驗區同事**阿文**解鎖會議用兩張圖 → 回電腦僅分享核准兩張圖，設定指定收件人唯讀與 7 天效期。
2. **誤寄後補救路線**：
   在電腦將整個 `ClearSky_TestData` 資料夾設成「持連結者皆可存取」寄出 → 收到合作方詢問能否轉傳協力廠商的急信 → 立刻回電腦**停用公開連結** → 找負責人**阿明組長**完成四要素通報（發現時間、涉及資料、使用系統、目前情況）。
3. **訪客拍照雙路線**：
   - 在**訪客入口指定角度**拍形象牆（核准範圍）。
   - 或**陪同進入實驗區**看相機預覽 → 發現白板／螢幕／樣品標籤入鏡時按「暫停拍攝」→ 整理現場後重拍。

### 第二章「投稿前一晚」（晚上 18:00）

阿文在辦公區門口請玩家協助確認今晚要交的研討會海報草稿（內含三張示意圖：圖一「設備配置示意」可公開、圖二「合作方量測圖」曾用於合作會議、圖三「測試條件與結果摘要」涉及尚待確認的專利申請安排）。

可自由走動調查**辦公區電腦**、**實驗區的阿文**（說明圖二來源並解鎖替代圖）與**辦公區的阿明組長**（詢問「現在哪張圖能用？」與「整理好之後怎麼確認版本？」），並在電腦比較「原始草稿」與「目前編輯版本」、送審核准與自選檔案提交。

#### 第二章三條測試路線

1. **核准後提交**：
   - 先到辦公區電腦看草稿（此時圖二顯示「來源待確認」且替代圖鎖定）→ 到實驗區找**阿文**確認圖二原用於合作會議並取得替代圖 → 找辦公區**阿明組長**確認公開規則與專利安排 → 回電腦替換圖二、移除圖三、送交阿明組長確認 → 找**阿明組長**核准該版本 → 回電腦核對檔名後提交核准版 → 回值班桌交班。
   - *額外驗證版本綁定*：取得核准版後再次編輯海報，確認會產生「待重新確認」的新版本，且原核准版紀錄保持不變。
2. **暫緩提交**：
   - 在未取得完整確認或發現合作資料公開用途／專利申請安排尚待確認時，於電腦「版本紀錄與提交投稿」分頁選擇**「暫緩上傳」** → 回值班桌交班，確認列出待確認的圖片、原因與下一步。
3. **誤傳舊版後補救（含未完成補救即交班）**：
   - 取得核准版後（或未核准前），在提交畫面故意選取未確認的舊版（如 `Poster_v1_原始草稿.pdf`）上傳 → 觸發誤傳警報。
   - **補救完成**：回電腦點「聯絡主辦方提出撤換請求」（顯示「已提出撤換請求，公開狀態待確認」）→ 找辦公區**阿明組長**回報 → 回值班桌交班確認撤換與公開狀態。
   - **未完成補救**：誤傳後直接回值班桌交班，確認交班畫面明確列出尚未處理的緊急項目。

### 第三章「今天的紀錄，明天找得到」（下午 16:30）

阿文剛完成一組薄膜量測，但原始檔仍留在儀器電腦、當日紀錄中有一筆樣品編號寫錯（`CS-2026-S03` 應為 `CS-2026-S08`），明天小晴將來盤點這批資料。玩家須實際上下 1F／2F 樓梯整理紀錄、歸檔原始檔與更新整批盤點清冊，再透過「模擬隔天盤點（小晴查找視角）」即時檢驗明天是否找得到、看得懂！

#### 第三章樓層與角色互動配置
- **2F（實驗區與辦公區）**：
  - **2F 實驗區 同事 阿文**：提供當日正確量測日期（`2026-11-22`）、樣品編號筆誤原因（`CS-2026-S03 → CS-2026-S08`）、實驗摘要與記錄人，取得後可在紀錄卡一鍵帶入。
  - **2F 實驗區 儀器電腦**：定位儀器本機上的原始量測檔（`CS_20261122_S08_RAW.csv`，全程維持唯讀原樣），可直接開啟「步驟二：選擇原始檔存放位置」。
  - **2F 實驗區 實驗紀錄桌**：開啟「步驟一：當日實驗紀錄卡（`LAB-2026-1122-01`）」，一鍵帶入線索、同步原始檔連結，並比較「直接覆寫舊內容」與「新增一筆更正紀錄（保留原值、原因、時間與更正人）」。
  - **2F 辦公區 值班電腦**：開啟三步驟整理工作台，為「本次量測資料」建立一筆整批盤點清冊（資料名稱或範圍、資料類型、保護原因、指定存放位置、負責人），並提醒不將機密技術參數寫入清冊。
  - **2F 辦公區 值班桌**：隨時執行「模擬隔天盤點（小晴查找視角）」並完成第三章交班。
- **1F（大門大廳）**：
  - **1F 大廳 盤點同事 小晴**：說明隔天盤點的四步查找順序（清冊 → 實驗紀錄 → 原始檔連結 → 更正歷程），亦可直接觸發模擬隔天盤點。
  - **1F 大廳 負責人 阿明組長**：依目前進度動態提示缺少哪個欄位、去哪裡找原始檔或如何留下可追溯的更正紀錄。
  - **1F 大門接待櫃台**：檢視「實驗室盤點清冊五欄位規範卡」。

#### 第三章四條測試路線

1. **完整整理＋系統原生更正（S 評價）**：
   - 找 2F 阿文取得日期／S03→S08／摘要／記錄人 → 到 2F 儀器電腦找到 `CS_20261122_S08_RAW.csv` 並移至「團隊指定資料夾」→ 到 2F 實驗紀錄桌帶入欄位、將原始檔連結同步更新為團隊指定資料夾、選擇「新增一筆更正紀錄（保留原值 S03）」→ 到 2F 值班電腦填齊整批盤點清冊五欄位（不含機密參數）→ 執行「模擬隔天盤點（小晴視角）」四步全數通過 → 完成交班。
2. **原始檔留在儀器電腦（未歸檔）**：
   - 不移動原始檔直接執行模擬隔天盤點 → 步驟三清楚提示檔案仍留在儀器電腦本機且具暫存風險，可返回歸檔重測。
3. **檔案已移轉至團隊資料夾，但紀錄卡連結未更新**：
   - 將檔案移至團隊指定資料夾後刻意不更新步驟一的連結 → 模擬隔天盤點步驟三明確呈現「檔案已移至團隊資料夾，但紀錄卡連結仍指向儀器電腦本機」的差異；回紀錄卡更新連結再重測即通過。
4. **直接覆寫舊值 → 查找顯示脈絡不明 → 事後補記**：
   - 在樣品編號更正處選擇「直接覆寫舊內容」→ 模擬隔天盤點步驟四顯示「無法確認樣品編號為何變更」→ 返回紀錄卡補上「事後補記」→ 模擬盤點與交班畫面均如實區分為「事後補記」，不等同於「系統原本保留的歷程」。

### 第四章「阿文的最後一天」（下午 17:00）

接續前章整理好的資料清冊，阿文即將離開實驗室，卻詢問能否先保留原本的專案資料夾權限以便下個月改論文。玩家需運用 1F 與 2F 樓梯／電梯完成跨樓層交接、切換「阿文／小晴」存取預覽視角、終止原權限、設定限期合作授權並收回實體門禁卡。

#### 第四章樓層與角色互動配置
- **1F（一樓大門大廳與入口櫃台）**：
  - **負責人 阿明組長**：核定阿文後續改論文所需的兩張圖（`ClearSky_會議用摘要圖_v2`）、用途（論文修訂）與相對期限（離開後 30 天），並提醒保密義務；若太早終止阿文原權限導致交接中斷，可請他由管理員單獨移交指定原始紀錄。
  - **1F 大門接待櫃台**：辦理阿文實體門禁卡收回與註銷登記（與電子權限各自獨立記錄）。
- **2F（二樓辦公區與量測實驗區）**：
  - **2F 值班電腦**：開啟「離職交接清單與存取視角預覽」，可即時切換「阿文視角」與「小晴視角」，檢查原始量測紀錄、兩張會議圖及無關專案資料之存取狀態，並執行小晴開權、兩張圖 30 天限期授權、終止或暫留原權限。
  - **2F 實驗區 同事 阿文**：協助將個人工作區的原始量測紀錄（`CS_2026_RawLog_Full.csv`）移交至專案指定位置；並透過對話完成離職後保密義務提醒與交還門禁卡。
  - **2F 實驗區 接手同事 小晴**：說明接手需求，並於檔案移交且權限開通後現場實測開啟，親自勾選交接清單「接收人已確認」。
  - **2F 實驗紀錄電腦**：對照交接清單位址（原位置與接手指定位置）及即時狀態。
  - **2F 值班桌**：檢視交接進度與完成第四章交班（支援帶著未完成待辦交班）。

#### 第四章三條測試路線

1. **完成交接與限期授權**：
   - 請 2F 阿文移交原始量測紀錄 → 在 2F 值班電腦為小晴開通專案權限（可在「小晴視角」看到已移交但無權限的差異）→ 請 2F 小晴實測開啟並確認接收 → 下樓找 1F 阿明組長核定兩張圖 30 天授權範圍並於 1F 櫃台收回門禁卡 → 回 2F 電腦終止阿文原權限並設定兩張圖 30 天限期授權（切換「阿文視角」確認只能看獲准兩張圖）→ 與 2F 阿文確認保密義務提醒 → 回 2F 值班桌交班。
2. **太早終止權限後補救**：
   - 在原始紀錄尚未移交前，先於 2F 值班電腦終止阿文原專案權限 → 找 2F 小晴（或阿文）確認交接中斷 → 下樓找 1F 阿明組長請求由管理員單獨移交指定紀錄（不恢復阿文整包原權限）→ 回 2F 確認小晴權限並請小晴實測開啟 → 補齊其餘項目後交班。
3. **保留原權限後發現授權過廣（直接交班 vs 補救後交班）**：
   - 於 2F 電腦點「先保留原權限」，切換「阿文視角」確認仍可存取與論文無關的其他專案資料。
   - 可選擇直接回 2F 值班桌交班（檢視原權限仍開放之風險與待辦事項），或回頭終止原權限、設定 30 天限期授權並完成所有交接後再交班。

## 日後部署到 GitHub Pages

1. 建立新的公開 Repository（例如 `before-sending-game`）。
2. **僅上傳本 `before-sending/` 資料夾內的檔案**（`index.html`、`css/`、`js/`、`audio/`、`README.md`）。
3. 到 Repository 的 **Settings → Pages → Build and deployment**，選擇 `Deploy from a branch` → `main` → `/ (root)` 儲存即可。
